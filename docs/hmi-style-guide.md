# 工业 HMI 组态风格指南（HP-HMI / ISA-101 落地版）

> 状态：**生效**（2026-11-24，随 `docs/plans/2026-11-24-iot-scada-screens-plan.md` 落地）。
> 适用范围：`src/symbols/` 的「工业功能件」图元与 `src/screen-assets/iot-screens.ts` 生成的
> 工业 SCADA 画面（`iot-*`）。旧深色演示画面（`home-*` / `demo-*` / `bi-*`）保持原样，不受本
> 指南约束——它们是"早期演示资产"，新画面才是组态规范基线。
>
> 依据：ISA-101.01-2015（显示层级/颜色使用）、ISA-18.2（报警优先级与冗余编码）、
> ISA-5.1 / ISO 10628 / ISO 14617（P&ID 图形语言）、High Performance HMI Handbook
> （灰阶底 + 异常才用饱和色），以及本仓 maotu 0.6.5 实证（`docs/maotu-symbol-development-guide.md`）。
> 设计论证与差距清单见 `docs/plans/2026-11-24-faceplate-and-industrial-hmi-architecture.md`。

## 0. 三类画面（操作层 vs 分析层 vs 空间层）

| 层 | 主题 | 画面 | 数据通道 | 用途 |
|---|---|---|---|---|
| **操作层** | HP-HMI 灰阶（L1 `#F0F0F0` / L2 `#DCDCDC` / L3 `#F5F5F5`） | `iot-plant-overview` / `iot-unit-*` / `iot-faceplate-*` | 通道 A（SSE 直写）+ 通道 B（就地历史趋势） | 实时工艺与设备诊断 |
| **分析层** | BI 深色大屏（`#0b0e14`） | `iot-bi-station` | 通道 B（宿主聚合） | 用量构成、排名、24h/7 天分析、告警统计 |
| **空间层** | 3D 场景（灰阶几何 + 异常饱和色，**独立文档与路由**） | `iot-plant-3d`（见 `docs/plans/2026-11-26-3d-hmi-design.md`） | 通道 A（SSE 直写） | 空间定位与导航、跨区域态势；点击设备进 2D 的 L2/L3 |

三层共用同一份 rs-iot 时序库与同一 BI 通道 B。深色只用于分析大屏——`ah-bi-*` 的 20 个图元
硬编码深色面板令牌（`BI_PANEL`），塞进灰阶操作层画面会像深色补丁；操作层要看历史时用
**浅色** `ah-hist-trend`（同一 BI 信封、浅色皮肤）。

**空间层与前两层的关系（2026-11-26 裁决）**：3D **不进 2D 画布**——它是独立的场景文档、
独立路由（`/view3d/:id`）、独立渲染器（**单一 WebGL 上下文**）。3D 只做"在哪、什么状态"，
精确读数与操作一律回 2D 的 L2/L3。视觉纪律（灰阶常态、异常才饱和色、三重冗余、禁写实）
对三层同时生效。

## 1. 显示层级（L1–L4）

| 层 | 目的 | 画面 | 约束 |
|---|---|---|---|
| L1 总览 | 全厂态势，防隧道效应 | `iot-plant-overview` | 只放区域卡（设备数/报警数/双 KPI）+ 全厂 P1 汇总；不放单点细节 |
| L2 单元 | 日常操作主界面 | `iot-unit-{water,power,gas,env}` | 工艺画面 + 就地值块 + 状态/报警徽标；单屏 ≤50~60 控制点 |
| L3 设备 | 诊断 | `iot-faceplate-{water,gas,power,env,pt}` | 一台设备全参数 + faceplate + 趋势；参数化（`@dev`）一屏服务同型 N 台 |
| L4 面板 | 最细操作/诊断 | 并入 L3（画布内 faceplate） | maotu 无弹窗/无嵌入画面能力，不做 WinCC 式弹出 |

导航约定：每张画面左上角固定「← 返回」+ 标题/副标题，右上角固定质量徽标 + 全厂报警徽标
+「报警」抽屉按钮。同类按钮位置在所有画面一致。

## 2. 颜色（HP-HMI 灰阶纪律）

单一事实源：`src/symbols/hp-hmi.ts`（`HP` / `prioColor` / `qualityColor`）。图元与画面
只引用它，不写散落色值。

| 角色 | 值 | 用途 |
|---|---|---|
| L1/L2/L3 底 | `#F0F0F0` / `#DCDCDC` / `#F5F5F5` | 画布底色（层级越深越亮，突出内容） |
| 面板底 | `#FFFFFF` | 值块/faceplate/区域卡内部 |
| 正文 | `#1F2328` | 标题、数值（正常态） |
| 次要文字 | `#5B6570` | 标签、单位、说明 |
| 静态图元 | `#5B6570` | 泵/阀/罐/管线的默认填充（正常态中性灰） |
| 活动数据 | `#1F4E79` | 实时值、趋势线（暗蓝，非饱和） |
| 第二数据通道 | `#2E6B52` | 双曲线时的第二条（暗绿） |
| P1 / P2 / P3 / P4 | `#D32F2F` / `#F57C00` / `#FBC02D` / `#1976D2` | **只**用于报警/异常/操作提示 |
| 正常/停止/离线 | `#2E7D32` / `#9E9E9E` / `#9E9E9E` | 状态徽标文字；不用于大面积填充 |

纪律：正常运行时屏幕上**不应出现饱和色**；饱和色出现即意味着"需要看这里"。
禁止渐变、投影、光泽按钮、装饰性着色、常亮动画。

**3D 的位置（2026-11-26 项目主宰裁决）**：3D **不受禁**——但**不与 2D 混搭**。3D 自成
**空间层**（独立的 3D 场景文档 + 独立路由 + 独立主题），不作为 2D 画布里的图元出现。
本文件其余条款（灰阶底、饱和色只用于异常、三重冗余编码、闪烁只表未确认）**同时约束
3D 空间层**：3D 里的设备几何同样用中性灰常态，异常才上饱和色；报警仍需形状/文字冗余。
两条细则：
- **禁止照片级写实**——3D 用平直着色（flat/matte）表达形体，不做 PBR 写实贴图；写实细节会
  与数据争夺注意力，违背 HP-HMI 的"只为辨识异常服务"。
- **不做 3D 文字精灵**——数值与文字一律用屏幕空间浮层（HTML overlay），不做贴图精灵；
  浮层只显示位号 + 一个关键值 + 状态词，**精确读数、趋势与操作一律回 2D 的 L2/L3 画面**。
  3D 的职责是"在哪、什么状态"，不是"读数"。

## 3. 报警编码（ISA-18.2 简化版）

- 优先级：P1 最高（红）、P2（橙）、P3（黄）、P4（蓝）。rs-iot 只有 `info|warn|error`
  三档，映射：`error→P1`、`warn→P3`、`info→P4`（P2 预留给联锁，本演示不使用）。
- **三重冗余**：颜色 + 形状 + 文字。P1 三角、P2 六边形、P3 方形、P4 圆形；文字必须
  带 `P<n>` 与数量（`×N`）。
- 活动报警徽标缓慢闪烁；清除后消失。rs-iot 无"确认(ack)"语义（只有 clear），
  因此本仓不伪装确认态——文档如实标注与 ISA-18.2 的差异。
- 限值判定在服务端（`scripts/limit-alarm/main.lua`，迟滞 2%），HMI 只显示结果，
  不在前端做阈值判定。

## 4. 字体与数字

- 标签：无衬线（`system-ui / Noto Sans SC / Microsoft YaHei`），12–14px，Sentence case，
  不使用全大写+字距装饰。
- 数值：**等宽 tabular 数字**（`Consolas / Menlo / monospace`），PV 22–32px，
  表格值 14–16px，单位小一号且用次要色。
- 小数位由工程精度决定（`precision` prop），不得按原始浮点全量显示。

## 5. 图元约定（工业功能件）

| 图元 | 语义 | 关键约束 |
|---|---|---|
| `ah-value-block` | 就地值块 | `prio>0` 数值转报警色；`quality>0` 数值转灰并显示质量字母；限值带标 LL/L/H/HH 刻线 |
| `ah-sparkline` | 迷你趋势 | 环形缓冲（`window` 秒），画限值线 + SP 线；不发起网络请求 |
| `ah-status-badge` | 状态徽标 | 形状冗余：运行圆、停止方、故障三角、维护菱形、离线圆+斜线 |
| `ah-alarm-badge` | 报警徽标 | `P1-P4` + 数量 + 形状；`prio=0` 时显示"正常"灰色 |
| `ah-quality-badge` | 质量徽标 | GOOD 灰绿、STALE 黄、BAD 红；文字必须出现 |
| `ah-pipe` | 工艺管线 | 粗实线 + 流向箭头；竖直段用 `binfo.angle=90` |
| `ah-area-card` | L1 区域卡 | 设备数/报警数/双 KPI/质量；点卡片进 L2（事件由生成器挂） |
| `ah-dev-faceplate` | 设备面板总成 | 标题/位号、PV+单位、限值带、偏差、趋势、状态/质量/报警；控制区（SP/OP/模式）由 `control` 开关控制，本演示关闭 |
| `ah-hist-trend` | 历史趋势（浅色） | 消费 BI 通道 B 信封（`props.data.val`）：多序列折线 + 量程标注；操作层画面就地看历史 |

新增图元必须：`fill` 为 color 型、props 键与 Vue 组件 `defineProps` 完全一致、
过 `symbol-lint` 七规则、进 `registry.ts` + `groups.ts` + `index.ts`（vue 组件）、
并在 `buildCatalogScreen()` 恰好出现一次（测试强制）。

## 6. 画面命名与 id

- 画面 slug：`iot-<层>-<单元>`（`iot-plant-overview` / `iot-unit-water` / `iot-faceplate-water`）。
- 元素 id：`<类型缩写>-<画面缩写>-<序号>`，全画面唯一，稳定（快照与 E2E 锚点）。
- 设备位号：`WM-101` / `GM-201` / `EM-301` / `ENV-401` / `PT-501`；描述用中文。
- 数据绑定：`<devid>.<tag>`（真实点）、`@dev.<tag>`（faceplate）、`__sys.*` / `__area.*` /
  `<devid>.__prio|__alarms`（宿主合成点，不进 SSE 订阅）。

## 7. 视觉走查（每次新增/改动画面必做）

1. 截图 L1/L2/L3 各一张（1280×800 画布，浏览器 1440 宽）。
2. 对照第 2/3 节自检：正常态是否无饱和色；报警是否三重冗余；数值是否有单位/限值。
3. 只修最影响观感的三处，最多两轮；记录问题与修法（计划文档任务表）。
4. 检查关键路径：L1→L2→L3(`?dev=`)→返回；报警触发→徽标变色→清除→恢复。

## 8. 验收（ISA-101 自检 10 项）

1. 任一画面 5 秒内可读出：当前值、是否越限、往哪偏、该做什么。
2. 正常态灰阶；饱和色只出现在异常与操作件。
3. 关键值旁有单位与 HH/H/L/LL 限值带。
4. 关键值旁有相邻趋势（含限值线）。
5. 报警 P1–P4 有色 + 形状 + 文字；活动闪烁、清除消失。
6. 同类操作在所有画面同一位置（报警右上、返回左下、设备选择器左上）。
7. L1/L2/L3 导航一致；L2 单屏 ≤60 控制点。
8. 工艺画面有管线、流向、设备位号，符合 ISA-5.1 基本形状。
9. 质量态（GOOD/STALE/BAD）与离线态可见，不把"没数据"画成"正常"。
10. 无渐变/投影/装饰色/常亮动画（3D 空间层另按 §2 的 3D 条款，不在 2D 画布内混搭）。
